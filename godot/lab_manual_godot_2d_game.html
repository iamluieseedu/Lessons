Milestone 1 Project Creation & Mobile Display Configuration

Godot 4 allows targeting desktop, mobile (Android/iOS), and web platforms with a single unified codebase. Configuring mobile display geometry and stretch policies before placing assets prevents distortion and pixel blurring across varying screen aspect ratios.

1
Create the Godot 4 Project
Project Setup
  1. Launch the Godot Engine 4.x Project Manager.
  2. Click New Project on the right sidebar.
  3. Set Project Name: Godot_2D_Mobile_Game.
  4. Click Create Folder to ensure a self-contained directory is generated on your filesystem.
  5. Under Renderer, select Mobile (Vulkan Mobile) or Compatibility (OpenGL 3 ES - highly recommended for maximum legacy mobile device support and low-spec laptops).
  6. Click Create & Edit to open the editor.
Compatibility vs Mobile Renderer: If your development workstation or target Android test devices do not support Vulkan drivers reliably, choose the Compatibility renderer. It starts significantly faster and renders standard 2D sprites with minimal overhead.
2
Configure Mobile Viewport & Stretch Settings
Project Settings

Navigate to Project > Project Settings > General > Display > Window and configure the following parameters:

Category / Sub-Section Property Name Value to Set Engineering Purpose
Display > Window > Size Viewport Width 1280 Target native landscape width in logical design pixels.
Display > Window > Size Viewport Height 720 Standard 16:9 720p base resolution for mobile gameplay.
Display > Window > Size Window Width Override 1280 (Optional) Window size when running on desktop workstation.
Display > Window > Stretch Mode canvas_items Crucial: Scales 2D canvas elements at native display resolution without pixelated scaling artifacts.
Display > Window > Stretch Aspect keep Preserves the 16:9 aspect ratio; adds subtle pillarboxes/letterboxes on ultra-wide screens rather than squishing sprites.
Display > Window > Handheld Orientation sensor_landscape Locks mobile orientation to landscape while allowing left/right rotation.
3
Enable Mouse Touch Emulation
Input Emulation
  1. In the same Project Settings modal, navigate to Input Devices > Pointing.
  2. Toggle Emulate Touch From Mouse to ON (Enabled).
  3. Click Save & Close.
Why Touch Emulation Matters: With Emulate Touch From Mouse enabled, your mouse clicks trigger touch screen events (InputEventScreenTouch), allowing you to build and test mobile touch gestures or virtual on-screen controls directly in the desktop editor!

Milestone 2 Blank Root Node & Background PNG Setup

In Godot, all gameplay elements are organized inside a hierarchical Scene Tree made of Nodes. We start with a blank 2D root node and anchor a single background PNG asset.

1
Create the Root Scene
Scene Hierarchy
  1. In the top-left Scene Dock, click the 2D Scene button (this automatically creates a root node of type Node2D).
  2. Double-click the created root node and rename it to Main (or GameLevel).
  3. Press Ctrl + S to save the scene as res://scenes/main.tscn (create a new folder named scenes inside the save dialog).
Initial Scene Tree Structure
Node2D Main (Root Scene Node at res://scenes/main.tscn)
2
Import & Add Background Image (PNG)
Visual Layer
  1. Create an assets/ folder in your FileSystem Dock (bottom-left).
  2. Drag your background image file (e.g. background.png, ideally 1280×720 or 1920×1080) into res://assets/.
  3. Right-click on the Main root node and select Add Child Node... (Ctrl + A).
  4. Search for Sprite2D (or TextureRect for UI anchoring) and click Create. Rename this child node to Background.
  5. With Background selected, look at the Inspector Dock on the right:
    • Locate the Texture property.
    • Drag background.png from the FileSystem dock into the empty Texture slot.
  6. Positioning and Centering:
    • Option A (Centered): Keep Offset > Centered checked, and set Transform > Position to Vector2(640, 360) (the exact midpoint of 1280×720).
    • Option B (Top-Left Origin): Uncheck Offset > Centered, and set Transform > Position to Vector2(0, 0).
  7. Z-Index Layering: Under the Ordering category in the Inspector, set Z Index to -10. This guarantees the background will always render behind the player, terrain, and UI elements.
Godot 2D Origin Rule: In Godot 2D space, the coordinates (0, 0) represent the Top-Left corner of the viewport. The X axis increases to the right (+X), and the Y axis increases downwards (+Y). Setting the position to (640, 360) places a centered 1280×720 image perfectly inside the screen bounds.

Milestone 3 Static Terrain & Ground Setup (TileMap or TextureRect)

Terrain in platform games must be solid and unyielding. In Godot 4, you can construct terrain surfaces using either TileMap with Physics Layer painting or a standalone StaticBody2D with TextureRect Tiling.

A
Method A: TileMap with 16×16 Physics TileSet
TileMap & Physics

Freely paint platforms and modular terrain using modular 16×16 pixel art tiles with built-in collision geometry:

  1. Right-click the Main root node > Add Child Node... > search for TileMap (or TileMapLayer in Godot 4.3+). Rename it to TerrainTileMap.
  2. In the Inspector Dock on the right, find the Tile Set property > click the dropdown > select New TileSet.
  3. Click on the newly created TileSet resource in the Inspector to expand its properties:
    • Set Tile Size to x: 16, y: 16 px (matching the Pixel Adventure terrain tiles).
    • Scroll down to expand Physics Layers > click Add Element. This creates Physics Layer 0 for solid collision queries.
  4. In the bottom panel, click on the TileSet dock tab. Drag Terrain (16x16).png from res://assets/ into the tiles panel.
  5. Godot will ask: "The image will automatically create tiles across the grid. Would you like to do this?" — click Yes.
  6. Click the Paint tab at the top of the TileSet panel > set Paint Property to Physics Layer 0. Click on each solid ground, surface, and wall tile to paint green collision polygons onto them.
  7. Switch from the TileSet panel to the TileMap dock tab at the bottom. Select your ground tiles and paint platforms across the 2D viewport!
TileMap Physics Advantage: Using TileMap physics layers allows you to paint multi-tier platforms, floating islands, and stairs in seconds without manually positioning individual collision rectangles for every single ledge.
B
Method B: TextureRect Tiled Platform (StaticBody2D)
StaticBody2D

Construct a continuous floor or rectangular platforms using a physical body with repeating tiled texture:

  1. Right-click the Main root node > Add Child Node... > search for StaticBody2D. Rename it to Ground.
  2. With Ground selected, add a child node: right-click Ground > Add Child Node... > search for CollisionShape2D.
  3. In the Inspector for CollisionShape2D:
    • Click the dropdown next to Shape > select New RectangleShape2D.
    • Set Size to x: 1280, y: 64.
  4. Add the visual ground surface: right-click Ground > Add Child Node... > search for TextureRect. Rename it to GroundVisual.
    • Drag your ground PNG into the Texture property.
    • Set Expand Mode to Ignore Size.
    • Set Stretch Mode to Tile.
    • Under Layout > Transform, set Size to x: 1280, y: 64 and Position to x: -640, y: -32.
  5. Select the parent Ground node and set its Transform > Position to Vector2(640, 688) to anchor it cleanly at the bottom of the 720p screen.
  6. Press Ctrl + G to group the node and its children so dragging never misaligns the collider.

Milestone 4 Player Character Assembly

In Godot 4, controllable 2D characters inherit from CharacterBody2D. This specialized node provides velocity-based movement, surface collision queries, and slope handling.

1
Assemble the CharacterBody2D Tree
Player Hierarchy
  1. Right-click Main > Add Child Node... > search for CharacterBody2D. Rename it to Player.
  2. Add the visual sprite: right-click Player > Add Child Node... > select Sprite2D. Rename it to PlayerSprite.
  3. In the Inspector for PlayerSprite, assign your character texture (e.g. Godot's default icon.svg or a character PNG sprite from res://assets/).
  4. Add the physics bounding box: right-click Player > Add Child Node... > select CollisionShape2D. Rename it to PlayerCollider.
  5. In the Inspector for PlayerCollider:
    • Select New CapsuleShape2D (or RectangleShape2D).
    • Adjust Radius and Height in the 2D viewport or inspector to tightly match the sprite's dimensions (e.g. Radius: 24, Height: 64).
  6. With Player selected, press Ctrl + G to lock its children into a unified object.
  7. In the 2D viewport, position the Player in the air above the terrain (e.g., Vector2(320, 300)). When we run the game, gravity will pull the character down onto the ground!

Milestone 5 GDScript Kinematic Movement & Physics Scripting

Event-driven programming in game engines couples user input signals with the fixed-rate physics integration loop. We will attach a complete GDScript to Player that queries input actions, accumulates gravitational acceleration, executes jump impulses, and solves collisions via move_and_slide().

1
Attach Script to Player Node
GDScript Scripting
  1. Select the Player (CharacterBody2D) node in the Scene tree.
  2. Click the Attach Script button (icon with a scroll and green plus) in the Scene dock toolbar.
  3. In the creation modal:
    • Language: GDScript
    • Inherits: CharacterBody2D
    • Template: CharacterBody2D: Basic Movement (or Default)
    • Path: res://scripts/player.gd (create a scripts folder)
  4. Click Create. Replace the contents of res://scripts/player.gd with the complete, production-ready script below:
res://scripts/player.gd 
extends CharacterBody2D

## 2D Kinematic Player Controller with Gravity, Jump, and Directional Input
## Designed for Mobile/Desktop 2D Platformer gameplay in Godot 4.

# Movement Constants
const SPEED: float = 300.0
const JUMP_VELOCITY: float = -450.0

# Fetch default 2D gravity value from Project Settings (default: 980 px/s²)
var gravity: float = ProjectSettings.get_setting("physics/2d/default_gravity")

# Reference to the child visual sprite
@onready var sprite: Sprite2D = $PlayerSprite

func _physics_process(delta: float) -> void:
	# 1. APPLY GRAVITY WHEN AIRBORNE
	# Godot 2D coordinates: +Y points downward towards the ground.
	if not is_on_floor():
		velocity.y += gravity * delta

	# 2. HANDLE JUMP IMPULSE
	# ui_accept corresponds to Spacebar, Enter, or Virtual Jump Button on mobile
	if Input.is_action_just_pressed("ui_accept") and is_on_floor():
		velocity.y = JUMP_VELOCITY

	# 3. READ HORIZONTAL INPUT AXIS
	# Input.get_axis returns a float from -1.0 (left) to +1.0 (right), or 0.0 if idle
	var direction: float = Input.get_axis("ui_left", "ui_right")

	# 4. COMPUTE HORIZONTAL VELOCITY & SPRITE FLIPPING
	if direction != 0.0:
		velocity.x = direction * SPEED
		# Flip sprite texture horizontally based on facing direction
		sprite.flip_h = direction < 0.0
	else:
		# Smooth deceleration towards 0 when no keys/joystick are held
		velocity.x = move_toward(velocity.x, 0.0, SPEED * 8.0 * delta)

	# 5. EXECUTE MOVE AND SLIDE COLLISION RESOLUTION
	# In Godot 4, move_and_slide() automatically uses the body's internal 'velocity'
	# and incorporates delta internally. It updates is_on_floor() automatically!
	move_and_slide()
2
Understanding the Code: Technical Breakdown
Code Analysis
Code Statement Type / Signature Architectural Explanation
extends CharacterBody2D Class Inheritance Exposes built-in kinematic properties (velocity, move_and_slide, is_on_floor).
_physics_process(delta) Lifecycle Callback Executed at a fixed 60 Hz physics tickrate, preventing frame-rate dependent tunneling.
velocity.y += gravity * delta Euler Integration Multiplies by delta (elapsed seconds ~0.0166s) so gravity acceleration is completely framerate independent.
JUMP_VELOCITY = -450.0 Impulse Constant Negative value because Godot's Y axis points downward. A negative velocity pushes the body upward.
Input.get_axis("ui_left", "ui_right") Axis Polling Evaluates directional buttons and returns a normalized float between -1.0 and +1.0.
move_and_slide() Kinematic Solver Calculates collisions against StaticBody2D, slides along geometry, and marks is_on_floor() = true upon impact.

Milestone 6 2D Physics Layers & Collision Masks

Why does the player land cleanly on the ground instead of falling into the void? The answer lies in Godot's Collision Layers and Collision Masks. Configuring these properly is essential for clean game architecture.

1
Name the 2D Physics Layers in Project Settings
Project Configuration
  1. Open Project > Project Settings.
  2. In the left panel, scroll down to Layer Names > 2D Physics.
  3. Define the following semantic layer names:
    • Layer 1: World (or Terrain)
    • Layer 2: Player
    • Layer 3: Enemies (for future labs)
    • Layer 4: Collectibles (for future labs)
  4. Click Close. Now, instead of raw bit numbers, the Inspector will display human-readable labels!

Collision Layer ("Who am I?")

Defines which physics channels this specific object exists on. Other objects in the game world can detect and collide with this body if their mask includes this layer.

Collision Mask ("What do I look for?")

Defines which physics channels this body actively scans and collides against. If an obstacle's layer is not checked in this body's mask, the body will pass through it like a ghost!

2
Configure StaticBody2D (Ground) Physics Layer
Terrain Collision
  1. Select the Ground (StaticBody2D) node in the Scene tree.
  2. In the Inspector, expand the Collision category:
    • Layer: Check Layer 1 (World) = ON. All other layers = OFF.
    • Mask: Set all bits to OFF (Static bodies never query moving objects; leaving Mask empty saves physics CPU calculations!).
3
Configure CharacterBody2D (Player) Physics Layer & Mask
Player Collision
  1. Select the Player (CharacterBody2D) node in the Scene tree.
  2. In the Inspector, expand the Collision category:
    • Layer: Check Layer 2 (Player) = ON. (The player resides on Layer 2).
    • Mask: Check Layer 1 (World) = ON. (The player actively scans Layer 1 to land on the terrain!).
Game Entity Node Collision Layer (Identity) Collision Mask (Scanning Query) Resulting Behavior
Ground (StaticBody2D) Layer 1 (World) None (Empty) Stationary platform. Emits physical boundary to scanning masks.
Player (CharacterBody2D) Layer 2 (Player) Layer 1 (World) Moves with velocity; immediately stops and slides when hitting Layer 1 terrain.
Launch & Test: Press F5 (or the Play button in top-right). If prompted, select res://scenes/main.tscn as the default main scene. Observe:
  • The player falls naturally under gravitational acceleration.
  • The player lands cleanly on the green terrain without clipping through.
  • Pressing A / D or ← / → moves the character left and right and flips the sprite.
  • Pressing Space or ↑ triggers a crisp jump that only activates when is_on_floor() is true!

Common Gotchas & Troubleshooting Guide

Issue: Player falls straight through the ground into the void

Diagnosis: Collision Mask mismatch or missing shape. Check that your Ground has an assigned RectangleShape2D (not empty). Verify that Ground has Layer 1 checked, and that Player has Mask 1 checked. If either is unchecked, no collision event occurs.

Issue: Player moves way too fast or teleports across screen

Diagnosis: Accidental double multiplication of delta. In Godot 4, move_and_slide() automatically applies delta internally! Never pass delta to move_and_slide() (unlike Godot 3's move_and_collide).

Issue: Pixel art sprites appear blurry or anti-aliased

Solution: Open Project Settings > Rendering > Textures > Canvas Textures > Default Texture Filter and change it from Linear to Nearest.

Issue: Dragging the player in the editor detaches the sprite from collider

Solution: Select the parent Player node and press Ctrl + G to enable "Make sure the object's children are not selectable". This ensures the entire hierarchy moves as one unit.
