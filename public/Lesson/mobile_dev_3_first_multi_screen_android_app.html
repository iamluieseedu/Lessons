Application Architecture & Screen Flow

In a multi-screen Android application, each distinct user screen is governed by an independent Activity class paired with an XML layout file. Transitions between screens do not happen through URL links like on the web; instead, they are requested via the Android operating system using Intents.

Here is the architectural journey you will build today:

======================================================================================== CAMPUSCONNECT: 4-SCREEN ARCHITECTURE FLOW ======================================================================================== +---------------------------------------------+ | MainActivity (Welcome Page) | | Logo + Title + Description + 2 Buttons | +---------------------------------------------+ | | [Click Login Button] [Click Sign Up Button] | | v v +-------------------------------+ +-------------------------------+ | LoginActivity | | SignUpActivity | | Username + Password Form | | Name + Email + Passwords | +-------------------------------+ +-------------------------------+ | | | | [Click "Create Acc"] [Valid: admin/1234] | [Click "Log In"] | | [Valid Form Submission] | +-------> (To SignUp) | | (To Login) <---+ | | (Passes "USER_NAME" extra) v v +-------------------------------+ | DashboardActivity | | "Welcome, [USER_NAME]!" | | 3 Dashboard Action Cards | | [LOG OUT] Button | +-------------------------------+ | [Click Logout Button] | v +-------------------------------+ | MainActivity (Returns to Home)| +-------------------------------+

The Explicit Intent Lifecycle

When a user touches a button, the calling Activity creates an explicit Intent specifying the target class. The Android OS receives this request, constructs the new Activity, executes its onCreate() lifecycle callback, inflates its XML visual tree, and pushes it onto the application's Back Stack.

User Taps Button ---> val intent = Intent(this, LoginActivity::class.java) startActivity(intent) | v (Android OS checks AndroidManifest.xml) LoginActivity is instantiated onCreate() fires setContentView(R.layout.activity_login) renders pixels!

Core Conceptual Pillars: Activity vs XML Layout

What is an Android Activity?

Think of an Activity as a single page or focused workstation in your app. In physical terms, if your application is a physical binder, each page inside that binder is an Activity.

  • MainActivity: The reception lobby (Welcome Page) welcoming the student.
  • LoginActivity: The security desk verifying credentials.
  • SignUpActivity: The registrar's desk gathering personal registration details.
  • DashboardActivity: The private student portal displaying personalized data.

What is an XML Layout?

An XML layout is the visual blueprint of an Activity. Just like HTML defines elements on a web page, XML specifies the position, dimensions, colors, margins, and hierarchy of every visual element (called a View) on the Android screen.

UI Component XML Tag Name Role in Our Application
Label / Text <TextView> Displays static or dynamic non-editable titles, descriptions, and greetings.
Input Field <EditText> Captures user typing (names, email addresses, masked passwords).
Action Button <Button> Triggers actions when tapped (Login, Register, Logout, Navigation).
Graphic / Icon <ImageView> Renders vector graphics, brand logos, and status illustrations.
Linear Container <LinearLayout> Stacks children linearly either vertically (top to bottom) or horizontally.
Scroll Container <ScrollView> Permits vertical scrolling when the software keyboard opens and covers inputs.

The Master Rule: "Where Does My Code Go?"

A universal point of confusion for beginner Android developers is deciding whether code belongs in an XML file, a Kotlin class, or the Manifest. Keep this reference table pinned while programming:

What I Am Building Target File Location in Project Tree Language
Screen Layout & Visual Blueprint activity_*.xml app > src > main > res > layout > XML
Button Styling, Colors & Margins activity_*.xml app > src > main > res > layout > XML
Color Palette Hex Values colors.xml app > src > main > res > values > XML
Re-usable Text Strings strings.xml app > src > main > res > values > XML
Button Click Event Listeners *Activity.kt app > src > main > java > [package] > Kotlin
Screen Navigation (Intents) *Activity.kt app > src > main > java > [package] > Kotlin
Form Validation & Passwords *Activity.kt app > src > main > java > [package] > Kotlin
Passing & Reading Data Across Screens *Activity.kt app > src > main > java > [package] > Kotlin
Registering Activities with the OS AndroidManifest.xml app > src > main > XML

Follow these exact steps inside your Arctic Fox environment:

  1. Launch Android Studio Arctic Fox (2020.3.1) from your desktop or start menu.
  2. In the Welcome dialog, click New Project. (If a previous project opens automatically, navigate to the top menu bar and select File > New > New Project...).
  3. In the New Project wizard window:
    • Look at the left-hand category pane and confirm Phone and Tablet is selected.
    • In the template grid, click on Empty Activity (represented by a white phone mockup with no blue header bars).
    • Click Next at the bottom right.
  4. On the Configure Your Project screen, enter the exact configuration below:
    • Name: CampusConnect
    • Package name: com.example.campusconnect
    • Save location: Leave as default or choose your course workspace.
    • Language: Kotlin (ensure Java is NOT selected).
    • Minimum SDK: Select API 21: Android 5.0 (Lollipop). This ensures your app runs on over 99% of global Android devices.
    • Leave "Use legacy android.support libraries" UNCHECKED (Arctic Fox uses modern AndroidX components).
  5. Click Finish at the bottom right.
  6. CRITICAL WAIT: Look at the bottom status bar. You will see "Gradle sync started". Arctic Fox is indexing dependencies, downloading Gradle 7.0.2 tooling, and building project symbols. Do NOT touch the editor or click buttons until the status bar displays "BUILD SUCCESSFUL" or "Gradle sync finished".

package com.example.campusconnect

import android.content.Intent
import androidx.appcompat.app.AppCompatActivity
import android.os.Bundle
import android.widget.Button

class MainActivity : AppCompatActivity() {

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        // 1. Inflate the XML visual layout onto this Activity window
        setContentView(R.layout.activity_main)

        // 2. Locate interactive button elements from the XML tree by their IDs
        val btnLogin = findViewById<Button>(R.id.btnLogin)
        val btnSignUp = findViewById<Button>(R.id.btnSignUp)

        // 3. Set a click listener to navigate to LoginActivity via an Intent
        btnLogin.setOnClickListener {
            val intent = Intent(this, LoginActivity::class.java)
            startActivity(intent)
        }

        // 4. Set a click listener to navigate to SignUpActivity via an Intent
        btnSignUp.setOnClickListener {
            val intent = Intent(this, SignUpActivity::class.java)
            startActivity(intent)
        }
    }
}
Notice the Red Text for LoginActivity and SignUpActivity? Don't worry! In Android Studio Arctic Fox, LoginActivity::class.java and SignUpActivity::class.java will temporarily appear in red because we have not created those Activity classes yet. We will create them in Parts 2 and 3 right now.

Step 2.3: Paste Login Kotlin Logic (LoginActivity.kt)

package com.example.campusconnect

import android.content.Intent
import androidx.appcompat.app.AppCompatActivity
import android.os.Bundle
import android.widget.Button
import android.widget.EditText
import android.widget.Toast

class LoginActivity : AppCompatActivity() {

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        setContentView(R.layout.activity_login)

        // Bind UI input elements
        val etUsername = findViewById<EditText>(R.id.etLoginUsername)
        val etPassword = findViewById<EditText>(R.id.etLoginPassword)
        val btnLogin = findViewById<Button>(R.id.btnPerformLogin)
        val btnGoToSignUp = findViewById<Button>(R.id.btnGoToSignUp)
        val btnBackToWelcome = findViewById<Button>(R.id.btnBackToWelcome)

        // Handle Login Submission
        btnLogin.setOnClickListener {
            val username = etUsername.text.toString().trim()
            val password = etPassword.text.toString().trim()

            // 1. Validate empty fields
            if (username.isEmpty() || password.isEmpty()) {
                Toast.makeText(this, "Please enter both username and password", Toast.LENGTH_SHORT).show()
                return@setOnClickListener
            }

            // 2. Educational Hardcoded Authentication (admin / 1234)
            // WARNING: FOR CLASSROOM DEMONSTRATION ONLY. NOT PRODUCTION AUTHENTICATION.
            if (username == "admin" && password == "1234") {
                Toast.makeText(this, "Authentication successful! Welcome, Admin.", Toast.LENGTH_SHORT).show()
                
                // Create Intent to Dashboard and attach user name
                val intent = Intent(this, DashboardActivity::class.java)
                intent.putExtra("USER_NAME", "System Administrator")
                startActivity(intent)
                finish() // Remove LoginActivity from back stack so user cannot 'back' into it
            } else {
                Toast.makeText(this, "Invalid credentials. Use admin / 1234", Toast.LENGTH_LONG).show()
            }
        }

        // Navigate to SignUpActivity
        btnGoToSignUp.setOnClickListener {
            val intent = Intent(this, SignUpActivity::class.java)
            startActivity(intent)
            finish()
        }

        // Back button returns to Welcome Screen
        btnBackToWelcome.setOnClickListener {
            finish() // Destroys LoginActivity and reveals MainActivity
        }
    }
}

package com.example.campusconnect

import android.content.Intent
import androidx.appcompat.app.AppCompatActivity
import android.os.Bundle
import android.widget.Button
import android.widget.EditText
import android.widget.Toast

class SignUpActivity : AppCompatActivity() {

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        setContentView(R.layout.activity_sign_up)

        // Bind UI input elements
        val etFullName = findViewById<EditText>(R.id.etSignUpFullName)
        val etEmail = findViewById<EditText>(R.id.etSignUpEmail)
        val etPassword = findViewById<EditText>(R.id.etSignUpPassword)
        val etConfirmPassword = findViewById<EditText>(R.id.etSignUpConfirmPassword)
        val btnSignUp = findViewById<Button>(R.id.btnPerformSignUp)
        val btnGoToLogin = findViewById<Button>(R.id.btnGoToLogin)
        val btnBack = findViewById<Button>(R.id.btnBackFromSignUp)

        // Registration form submission handler
        btnSignUp.setOnClickListener {
            val fullName = etFullName.text.toString().trim()
            val email = etEmail.text.toString().trim()
            val password = etPassword.text.toString().trim()
            val confirmPassword = etConfirmPassword.text.toString().trim()

            // 1. Check for empty fields
            if (fullName.isEmpty() || email.isEmpty() || password.isEmpty() || confirmPassword.isEmpty()) {
                Toast.makeText(this, "Error: All fields are required!", Toast.LENGTH_SHORT).show()
                return@setOnClickListener
            }

            // 2. Check for basic email format
            if (!email.contains("@") || !email.contains(".")) {
                Toast.makeText(this, "Please enter a valid email address", Toast.LENGTH_SHORT).show()
                return@setOnClickListener
            }

            // 3. Password length validation
            if (password.length < 6) {
                Toast.makeText(this, "Password must be at least 6 characters", Toast.LENGTH_SHORT).show()
                return@setOnClickListener
            }

            // 4. Password matching validation
            if (password != confirmPassword) {
                Toast.makeText(this, "Passwords do not match! Please check again.", Toast.LENGTH_SHORT).show()
                return@setOnClickListener
            }

            // 5. Successful registration: Navigate to Dashboard and pass user's name
            Toast.makeText(this, "Registration successful! Welcome to CampusConnect.", Toast.LENGTH_SHORT).show()

            val intent = Intent(this, DashboardActivity::class.java)
            intent.putExtra("USER_NAME", fullName) // Attach the real typed name
            startActivity(intent)
            finish()
        }

        // Navigate to Login screen
        btnGoToLogin.setOnClickListener {
            val intent = Intent(this, LoginActivity::class.java)
            startActivity(intent)
            finish()
        }

        // Return to Welcome screen
        btnBack.setOnClickListener {
            finish()
        }
    }
}

Part 4: How Data Passing Works (putExtra vs getStringExtra)

In Android, Activities are isolated from one another. You cannot directly access variables from another Activity. To transport data (such as a registered student's name), Android provides an Extras Dictionary (Bundle) inside the Intent.

+---------------------------------------------------------------------------------+ | HOW INTENT EXTRAS TRANSPORT USER DATA | +---------------------------------------------------------------------------------+ 1. SENDER ACTIVITY (SignUpActivity.kt) val typedName = "Maria Santos" val intent = Intent(this, DashboardActivity::class.java) intent.putExtra("USER_NAME", typedName) <--- Stores Key-Value: ("USER_NAME" -> "Maria Santos") startActivity(intent) | | (Operating System carries the Intent across the screen boundary) v 2. RECEIVER ACTIVITY (DashboardActivity.kt) val receivedName = intent.getStringExtra("USER_NAME") <--- Retrieves "Maria Santos" using exact key! tvGreeting.text = "Welcome, $receivedName!"
THE GOLDEN RULE OF INTENT EXTRAS: The Keys Must Match Exactly! If you write intent.putExtra("USER_NAME", fullName) in the sender, but write intent.getStringExtra("userName") (lowercase) or intent.getStringExtra("NAME") in the receiver, the extra will return null! The key string is strictly case-sensitive.

Part 6: Understanding Android Activity Stack & Logout

When a user logs out, we do not simply launch MainActivity; we also clear the previous screens from Android's Task Back Stack.

If we merely called startActivity(Intent(this, MainActivity::class.java)) without flags, touching the physical Android Back Button on the phone would send the student right back into the private Dashboard without logging in!

Without Task Flags: [MainActivity] -> [LoginActivity] -> [Dashboard] -> [Taps Logout] -> [MainActivity] | (Pressing Back reveals Dashboard!) WITH FLAG_ACTIVITY_CLEAR_TOP and finish(): [MainActivity] -> [LoginActivity] -> [Dashboard] -> [Taps Logout] | v All intermediate screens are destroyed! Back stack is reset to clean [MainActivity].

The Gateway: Understanding AndroidManifest.xml

Open app > src > main > AndroidManifest.xml. Every Activity you create in Kotlin MUST be registered in this XML document. If you create an Activity in Kotlin but omit its declaration here, Android will crash with an ActivityNotFoundException when you try to open it!

app > src > main > AndroidManifest.xml 
<?xml version="1.0" encoding="utf-8"?>
<manifest xmlns:android="http://schemas.android.com/apk/res/android"
    package="com.example.campusconnect">

    <application
        android:allowBackup="true"
        android:icon="@mipmap/ic_launcher"
        android:label="@string/app_name"
        android:roundIcon="@mipmap/ic_launcher_round"
        android:supportsRtl="true"
        android:theme="@style/Theme.CampusConnect">

        <!-- 1. MAIN LAUNCHER: MainActivity launches when user taps app icon -->
        <activity
            android:name=".MainActivity"
            android:exported="true">
            <intent-filter>
                <action android:name="android.intent.action.MAIN" />
                <category android:name="android.intent.category.LAUNCHER" />
            </intent-filter>
        </activity>

        <!-- 2. Child Activities: Exported=false ensures external apps cannot launch them -->
        <activity
            android:name=".LoginActivity"
            android:exported="false" />

        <activity
            android:name=".SignUpActivity"
            android:exported="false" />

        <activity
            android:name=".DashboardActivity"
            android:exported="false" />

    </application>

</manifest>

Troubleshooting: Top 8 Beginner Errors & Fixes

Error 1: Button click does absolutely nothing

Cause: You created the button in XML but forgot to assign a click listener in Kotlin, or your findViewById(R.id.yourButton) points to the wrong ID.

Fix: Verify that the ID in your XML matches the ID in Kotlin exactly: android:id="@+id/btnLogin" ↔ findViewById<Button>(R.id.btnLogin). Ensure button.setOnClickListener { ... } is written inside onCreate().

Error 2: Application crashes immediately when clicking Login or Sign Up

Cause: android.content.ActivityNotFoundException: Unable to find explicit activity class.

Fix: Open AndroidManifest.xml and confirm the activity is declared inside <application>: <activity android:name=".LoginActivity" />.

Error 3: XML shows red lines: "Unclosed tag" or "Missing namespace"

Cause: Missing closing tag (e.g. />) or missing xmlns:android="http://schemas.android.com/apk/res/android" on the root layout element.

Fix: Every opened tag like <TextView ...> must end with /> or a corresponding </TextView>. Ensure the top layout has the xmlns:android namespace.

Error 4: "Unresolved reference: R" or "R.id.* cannot be resolved"

Cause: Android Studio imported android.R instead of your local project's R file, or a syntax error in an XML layout prevented R.java from generating.

Fix: Check your imports at the top of your Kotlin file. If you see import android.R, DELETE IT. Then select menu: Build > Clean Project followed by Build > Rebuild Project.

Error 5: "Activity cannot be found" or red class highlight

Cause: Package mismatch or filename spelling error (e.g., loginactivity vs LoginActivity).

Fix: Kotlin class names are case-sensitive. Check that your file is named LoginActivity.kt and the class declaration reads class LoginActivity : AppCompatActivity().

Error 6: Password appears as normal visible text

Cause: The EditText is missing android:inputType="textPassword".

Fix: In activity_login.xml and activity_sign_up.xml, add android:inputType="textPassword" to mask characters with dots.

Error 7: Dashboard displays "Welcome, Student!" instead of the typed name

Cause: Intent Extra key spelling mismatch between sender and receiver.

Fix: Check the key string in both files: In SignUpActivity.kt: intent.putExtra("USER_NAME", fullName) ↔ In DashboardActivity.kt: intent.getStringExtra("USER_NAME"). The key string must be identical!

Error 8: Gradle sync failed or build stuck

Cause: Gradle synchronization interrupted, or offline cache conflict.

Fix: In Arctic Fox, select File > Sync Project with Gradle Files. If issues persist, select File > Invalidate Caches / Restart... and select Invalidate and Restart.
